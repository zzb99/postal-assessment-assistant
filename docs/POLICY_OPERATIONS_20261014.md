# 制度发布与恢复操作说明

普通职工不需要登录或审批。主管和管理员在后台制度查询页都能直接上传、下载原件和恢复历史制度；职工、只读领导无发布及恢复权限。

选择 DOCX，填写唯一版本号及生效日期，可先点击“查看条款变化”，核对新增、修改、移除条目及金额变化，再直接发布。差异记录包含旧版规则 ID、原文 SHA-256 和前后原文。初次从旧 JS 目录切换到 Word 解析目录时，两种解析器的分段方法不同，“新增/移除条目”不等于正文实际增删，必须结合原 Word 和表格行定位核对。原 Word、全部非空正文块、表格行及附件保留；自动编号显示仍以原件为准。

固定金额、每次、每件的简明单价由本地解析处理，首次解析展示为候选，发布时与旧版比较后才启用。旧条款的金额/条件变化、复杂组合、区间、时间条件、表格和附件不自动定价。此前核准的 8 条只在环节与完整原文相同的情况下继承。AI 只选条款和整理语言，不计算金额；事实核对和数量补充均在本地继续，不重复调用模型。

新版按检查日期适用，尚未到生效日期的版本不用于该日期之前出单。历史恢复从恢复操作当天起生效，不改写更早日期的适用版本，也不重新生成历史文书。历史单据下载始终读取原归档文件。

制度位于 DOCUMENT_ROOT/policies（Docker 默认 /data/documents/policies），包括原件、JSON 目录、manifest.json、操作日记和锁文件。API 使用单 Worker，发布与审计在跨进程文件锁内串行完成；中断后根据数据库审计标记恢复前态或已提交态。备份必须同时包含 PostgreSQL 与整个文书卷，不能只复制 Word 文件或只备份数据库。

发布后，同一页面的查询目录会重新加载，其他后台标签页在重新获得焦点时刷新。AI 缓存和签名绑定目录摘要，制度变更时旧结果不能套用新金额。过期/失效结果保留正文，仍可按新制度重新核对或走手动路径。

当期真实制度原件及生效日期仍需业务方确认，特别是原交接提及但本包没有提供的 20260825 版；不得由模型补造或混用。
