# 识别链路专项修复 r3（2026-10-14）

基于用户指定修复ZIP的隔离源码继续增量修改。r2代码基线为30c5082；未更换Word模板、未增加职工审批、未操作生产环境。

## 修改

1. 将具体问题与作业环节分开检索。遗留、垃圾桶、缺员、暴力分拣等行为优先；保留通用规定，降低不相关环节与大段附件的优先级。保留候选相关性顺序，发送模型时附环节与排名，最多6条。
2. “小件机遗留1件”等简写增加检索扩展，不将扩展词写入现场事实。被选择条款须通过本地问题对应检查；模型仅引用地点的依据不予接受。缺少模型依据时，可从原始事实独立提取已知行为依据，否则保持待选择。
3. 事实段只允许轻微格式整理，无法验证的扩写回退原始描述。模型改数字、位置、时限、违规过程不再带入正文；整改仍单独校验。不能把“未及时清理”认定为“未执行一小时一清”。
4. 整改专项用语逐项与事实绑定，防止工服问题出现吸烟整改，遗留问题出现三角看袋或异常邮件每小时清理要求。清理“望公司请责任单位”重复称呼。
5. 实调发现deepseek-flash将conditionsSatisfied返回为条件ID数组，导致完整案例也被要求再次总括确认。已明确布尔字段类型，并仅兼容恰好等于所选计费条件集合的无重复字符串数组。本地calculate仍独立依据原始事实/人工回答核算，模型条件不能替代证据，未知other条件不会被清除。
6. 手机界面默认显示最多3条相关依据；完整稿默认显示本单依据。其他候选可展开。选择条款、条件续填不重调收费模型。仍使用deepseek-flash与本地缓存。

## 范围与剩余风险

- 12例是定向合成实调，不是独立历史业务集，不能承诺95%整体准确率。需要业务标注的独立历史考核单继续评估最终条款、适用条件和金额。
- 事件词表不可能覆盖全部口语；多事件合并、未覆盖词汇、复杂附件/区间金额仍可能需要核对。检索词只帮助找条款，不能证明时长、出局、异常性质等条件。
- 完全不说明遗留位置、异常性质或时长的简写，制度本身存在不同适用标准，系统不能合法从1件猜成1次或猜出金额。此类情况保留正文并提出必要核对。
- 修复会使旧AI缓存/签名失效；浏览器草稿保留，需重新整理一次。后续同条件重复操作仍使用缓存。
- 未增加第二模型或无限重试。配置价格仅为估算，实际账单未读取。
- 本轮付费评测25次、浏览器验证1次，合计45,276 Token；配置估算0.03562936元。初轮失败和诊断调用也计入，未只计算最终成功样本。
