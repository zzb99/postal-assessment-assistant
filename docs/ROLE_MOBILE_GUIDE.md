# 主管与职工工作台改造（2026-10-09）

> 2026-10-13 更新：默认职工入口已由免登录快捷填报替代，且按用户新要求直接正式生成、不再主管复核。下文仅描述旧账号工作台；当前行为见 QUICK_MOBILE_GUIDE.md。

## 权限与流程

| 角色 | 数据范围 | 可操作 | 不可操作 |
| --- | --- | --- | --- |
| 职工 employee | 本部门且本人创建的记录 | 新建、修改本人草稿、复制、查看本人归档文书、查询制度 | 正式生成、作废、批量导出、分组统计、账号管理 |
| 主管 department_manager | 本部门记录 | 复核/修改草稿、正式生成、作废、导出、统计、查询制度 | 跨部门查看/生成/作废、系统管理 |
| 管理员 admin | 全部记录 | 业务管理、账号与基础数据管理 | 修改已正式生效的考核单 |
| 历史领导 leader | 全部记录，只读 | 台账、文书、导出、统计、制度查询 | 建单、修改、正式生成、作废、系统管理 |

职工保存的记录是草稿，主管可在台账点击“复核草稿”打开原记录，核实事实和金额后生成；这不是新增的多级审批流程，也没有单独“已提交”状态。主管与职工账号必须绑定部门。检查人仍由班组名册选择，不擅自把登录账号当成检查人。

权限在 API 执行。职工的列表、详情、更新、复制及 Word/PDF 下载同时限制所属部门和创建者；未知角色、未绑定部门账号拒绝访问。每个请求从数据库读取当前账号权限，旧 token 不保留撤销前的权限。

## 防止覆盖与正式文书一致性

- 更新草稿保留完整微秒版本，使用行锁及条件 UPDATE（状态、版本），冲突返回 409。
- `POST /api/assessments/{id}/finalize` 现在必须提交 JSON `{"updated_at":"该草稿最近一次读取或保存返回的时间"}`；缺少版本返回 422，过期版本返回 409。
- 前端正式生成先保存当前内容，再提交该保存版本。转换失败保留原草稿 ID，重试不重新创建重复草稿。
- 正式生成期间禁止继续编辑表单，避免生成成功后丢失等待期间输入。
- 退出/换号后旧列表、管理刷新、AI 结果不会写回新会话，旧文件响应不能自动触发下载。
- 导出 Excel 中的所有字符串强制为文本，员工填写的等号开头内容不执行为公式。

新前端与 API 需一起部署；旧前端未携带定稿版本，不应与新 API 混用。角色列是现有字符串列，本次没有改表结构或重建数据。

## 手机布局

- 640px 以下底部固定导航，预留安全区；职工只有工作台、填报、本人记录、制度查询四个入口。
- 单列表单、可选项折叠、至少 44px 点击目标和 16px 输入字号。
- 台账使用同一份记录，在桌面显示表格、窄屏显示有字段标签的卡片；不需要横向拖动阅读业务记录。
- 首页使用无筛选的独立记录源，不受台账筛选条件影响。

## 密钥状态

`GET /api/ai/status` 需登录，只返回 enabled 布尔值，不返回密钥。未启用 AI 时可手动填报和关键词查询正式制度目录（319条）。本地和已检查的私有配置未找到可用 DeepSeek 密钥，因此真实 AI 调用仍未验收。密钥只应作为服务端 DEEPSEEK_API_KEY 环境变量配置，不能放入前端。
